## 1. Architektura i struktura projektu

**Ocena: Dobra**

Projekt ma czytelną separację odpowiedzialności:
- `models.py` — dataclasses dla danych
- `database.py` — warstwa persystencji

## 2. Bezpieczeństwo

### 2.1. Credentials w repozytorium
**Priorytet: WYSOKI**

Plik `client_secret_*.json` jest w `.gitignore`, ale **sam plik istnieje w katalogu projektu**. `credentials.pickle` również. Plik `.gitignore` poprawnie je wyklucza, ale:
- Brak weryfikacji czy `credentials.pickle` jest wciąż ważny (expired token) przed użyciem — `pickle.load()` załaduje nieaktualny token, co spowoduje błąd API dopiero w trakcie działania.
- Użycie `pickle` do przechowywania credentials to potencjalne ryzyko — pickle jest podatny na deserializację złośliwych danych. W tym kontekście (lokalny projekt) ryzyko jest minimalne, ale lepszą praktyką byłoby użycie `google.auth.transport.requests.Request` do odświeżania i `json` do serializacji.

### 2.2. Brak walidacji danych z API
**Priorytet: ŚREDNI**

Dane z YouTube API są wstawiane do bazy SQLite przez parametryzowane zapytania (bezpieczne przed SQL injection), ale nie ma walidacji samych wartości (np. czy `published_at` jest poprawnym formatem daty). Niepoprawne dane mogą powodować ciche błędy w filtrach i sortowaniu.

### 2.3. Bare except w `tui.py`
**Priorytet: NISKI**

Linie `tui.py:258` (`_open_in_browser`) i `tui.py:287-288` (`_set_shorts_threshold`) używają gołych `except:` bez specyfikacji wyjątku. Może to maskować nieoczekiwane błędy.

## 3. Stabilność i obsługa błędów

### 3.1. Podwójne logowanie błędów synchronizacji
**Priorytet: NISKI**

`main.py:12-16` konfiguruje `logging.basicConfig` z plikiem `sync_error.log`, ale `main.py:129-131` ręcznie otwiera ten sam plik i dopisuje do niego. To powoduje duplikaty wpisów i niespójny format (logging z datą + ręczne `datetime.now()`).

**Rekomendacja:** Usunąć ręczne pisanie do pliku i użyć wyłącznie modułu `logging`:
```python
logger.error("Sync error: %s", e, exc_info=True)
```

### 3.2. Brak odświeżania tokena OAuth
**Priorytet: WYSOKI**

`youtube_client.py:52-63` — `_get_authenticated_service()` ładuje credentials z pickle, ale nie sprawdza `credentials.expired` ani nie wywołuje `credentials.refresh()`. Po wygaśnięciu tokena (typowo 1h) synchronizacja zakończy się błędem API 401 bez jasnego komunikatu dla użytkownika.

**Rekomendacja:**
```python
if credentials.expired and credentials.refresh_token:
    credentials.refresh(google.auth.transport.requests.Request())
    with open(CREDENTIALS_PICKLE, "wb") as f:
        pickle.dump(credentials, f)
```

### 3.3. ThreadPoolExecutor — brak obsługi wyjątków w `fetch`
**Priorytet: ŚREDNI**

`main.py:52-62` (`download_thumbnails.fetch`) — wewnętrzna funkcja `fetch` łapie wszystkie wyjątki per URL, ale nie loguje ich. Ciche awarie pobierania miniatur mogą być trudne do zdiagnozowania.

### 3.4. `get_channel_stats` — datetime bez timezone
**Priorytet: NISKI**

`database.py:230-231` — `datetime.now().timestamp()` zwraca czas lokalny, ale porównuje go z datami w formacie UTC (`%Y-%m-%dT%H:%M:%SZ`). Powinno być `datetime.now(timezone.utc)`.

## 4. Wydajność

### 4.1. Liniowe wyszukiwanie wybranego filmu
**Priorytet: ŚREDNI**

`tui.py:171-176` (`_get_selected_video`) i `tui.py:185-188` (`_find_current_display_index`) iterują po całej liście filmów przy każdym odświeżeniu ekranu. Przy kilku tysiącach filmów to jest niezauważalne, ale przy dziesiątkach tysięcy może powodować lagowanie.

**Rekomendacja:** Utrzymywać `dict` mapujący `video_id -> Video` dla O(1) lookup.

### 4.2. `save_videos` — brak batch INSERT
**Priorytet: NISKI**

`database.py:113-131` — filmy wstawiane są jeden po jednym w pętli. `executemany()` z listą tupli byłoby wydajniejsze dla dużych synchronizacji (setki/tysiące filmów).

### 4.3. `sync_data` — liniowe wyszukiwanie kanału
**Priorytet: NISKI**

`youtube_client.py:339-342` — po zakończeniu każdego future'a, pętla szuka kanału po ID iterując po liście kanałów. Przy ~500 kanałach to O(n) zamiast O(1) z `dict`.

### 4.4. Brak indeksów w SQLite
**Priorytet: ŚREDNI**

Tabela `videos` nie ma indeksu na `published_at` (używanym w `ORDER BY` i `WHERE` w `get_channel_stats`), ani na `channel_id` (używanym w `GROUP BY`). Przy rosnącej bazie (obecna ma ~29 MB) indeksy znacząco przyspieszą zapytania.

**Rekomendacja:**
```sql
CREATE INDEX IF NOT EXISTS idx_videos_published_at ON videos(published_at);
CREATE INDEX IF NOT EXISTS idx_videos_channel_id ON videos(channel_id);
```

## 5. Poprawność logiki

### 5.1. Filtr "Shorts" wyklucza filmy z `duration_seconds == 0`
**Priorytet: ŚREDNI**

`tui.py:141` — warunek `video.duration_seconds < threshold` odfiltruje filmy z nierozpoznanym formatem czasu trwania (zwracające 0), traktując je jako Shortsy. Dotyczy to np. streamów live bez zakodowanego czasu trwania.

**Rekomendacja:** Zmienić warunek na:
```python
if not self.show_shorts and 0 < video.duration_seconds < threshold:
```

### 5.2. Porównanie dat jako stringów
**Priorytet: NISKI**

`youtube_client.py:235` — `video_pub_at < published_after` porównuje daty jako stringi. Działa poprawnie dla formatu ISO 8601 `YYYY-MM-DDTHH:MM:SSZ`, ale jest kruche — jeśli YouTube zmieni format odpowiedzi, porównanie się zepsuje bez widocznego błędu.

### 5.3. `_safe_addstr` obcina o jeden znak za dużo
**Priorytet: NISKI**

`tui.py:208` — `str(text)[:available-1]` obcina tekst do `available-1` znaków. Powinno być `[:available]`, chyba że intencją jest zachowanie marginesu (ale wtedy przy `available == 1` tekst będzie pusty, co jest poprawne, ale przy `available == 0` dostaniemy pełny tekst z powodu semantyki slice'a z ujemnym indeksem).

**Rekomendacja:** Dodać guard `if available <= 0: return` przed `addstr`.

### 5.4. `page_scroll_ratio` jest nieużywane
**Priorytet: NISKI**

Konfiguracja `ui.page_scroll_ratio` jest zdefiniowana w `config.json` i w domyślnych wartościach, ale nigdzie nie jest odczytywana. PageUp/PageDown przewijają o `sh - 2`, nie o konfigurowalny procent.

## 6. Jakość kodu

### 6.1. Plik `tui.py` — 1082 linie
**Priorytet: ŚREDNI**

Cała logika TUI jest w jednym pliku i jednej klasie. `_handle_key` (linie 760-939) to 180-liniowy `if/elif` chain. Metoda `run` (941-1064) łączy pętlę zdarzeń, rendering, input i logikę synchronizacji.

**Rekomendacja:** Rozważyć wydzielenie:
- Obsługi klawiszy do osobnej metody/dispatch table
- Renderowania paneli do osobnych klas/modułów

### 6.2. Magic numbers w kolorach
**Priorytet: NISKI**

`tui.py:92-113` — pary kolorów curses (1-15) przypisane ręcznie. Wystarczyłyby stałe (np. `COLOR_HEADER = 1`), żeby łatwiej mapować pair numbery do ich znaczenia.

### 6.3. Brak type hints dla `_get_authenticated_service`
**Priorytet: NISKI**

`youtube_client.py:46` — metoda nie ma return type hint. Powinno być `-> googleapiclient.discovery.Resource` (lub `-> Any` jeśli nie chcemy importować typu).

### 6.4. Duplikacja logiki pobierania miniatur
**Priorytet: NISKI**

Logika pobierania miniatur z fallbackiem (`maxresdefault.jpg` -> `thumbnail_url`) jest zduplikowana w `main.py:54-62` (`download_thumbnails.fetch`) i `tui.py:366-380` (`_kitty_encode`). Przy zmianie kolejności fallbacków trzeba pamiętać o obu miejscach.

## 7. Konfiguracja i deployment

### 7.1. `pyproject.toml` — generyczne metadane
**Priorytet: NISKI**

`name = "script"`, `description = "Add your description here"` — wartości domyślne, niezmienione po `uv init`. Warto uzupełnić, szczególnie jeśli projekt miałby być współdzielony.

### 7.2. Brak obsługi brakujących zależności systemowych
**Priorytet: NISKI**

Aplikacja zależy od `mpv`, `xclip`/`wl-copy`, `xdg-open` — ich brak nie jest sygnalizowany (ciche `FileNotFoundError` w `_copy_to_clipboard`, brak komunikatu w `_play_video`).

### 7.3. Hardkodowana ścieżka bazy danych
**Priorytet: NISKI**

`database.py:7` — `DB_PATH = "youtube_monitor.db"` jest globalną stałą. Nie da się uruchomić aplikacji z alternatywną bazą (np. do testów) bez edycji kodu.
